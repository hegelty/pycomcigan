# 2026-11-07 컴시간 조회 변경 대응

이슈: https://github.com/hegelty/pycomcigan/issues/11

기존 학교 검색 요청은 HTTP 200과 `{}`를 반환한다. `_enc2`를 붙이는 이전 대응도 현재 서버에서는 동작하지 않는다. 공식 `/st` 페이지에서 다음 처리를 확인했다.

- `hour-obfuscated-v2` 내부의 `hour-ajax-obfuscated-v1` 래퍼까지 데이터로 복원한다. JavaScript를 실행하지 않는다.
- 학교 검색은 `검색접두사 + encodeURIComponent(검색어) + "_enc5"`를 Base64로 인코딩하고, 그 결과를 다시 URI 인코딩한다. 검색어 인코딩은 UTF-8이다.
- 시간표는 `요청코드_학교코드_0_주차_enc5`를 Base64로 인코딩한다.
- 경로, 검색접두사, 요청코드, 자료 필드 번호, 키 조각·연결 순서, 학교 코드 열 계산식은 페이지에서 읽는다. 서버의 현재 숫자나 키를 고정하지 않는다.
- `QAjaxSchool`과 `QAjaxTimetable`의 요청 경로·암호화 버전을 대조한다. 시간표 요청 함수가 없거나 두 값이 어긋나면 요청을 보내기 전에 페이지 형식 변경 오류로 중단한다. 학교 코드 열 계산식은 양수 divisor와 0~64 범위 offset만 허용한다.
- 응답은 `enc5:Base64(IV):Base64(암호문):Base64(인증값)`이다. 정규 인코딩과 길이를 확인한 뒤 `HMAC-SHA256(SHA256(K), "enc5:IV:암호문")`을 상수 시간 비교한다. 인증에 성공해야 AES-CBC/PKCS7 복호화, UTF-8 디코딩, 끝 NUL 제거, JSON 파싱을 수행한다. 공식 페이지가 함께 지원하는 `enc1`의 소문자 Hex 형식도 처리한다.
- 학교 코드 열은 페이지의 `floor(row[0] / divisor) + offset`으로 선택한다. 반환 행은 기존의 네 열 `[지역 코드, 지역명, 학교명, 학교 코드]`로 정규화하고 안내 행은 제외한다.
- 암호화 요청에 평문 `{}`가 돌아오면 프로토콜 오류로 처리한다. 정상 검색의 빈 목록과 구분한다. 구형 페이지의 평문 JSON 처리는 유지한다.

두 종류의 난독화 래퍼는 순서와 관계없이 최대 4단계까지 복원하고, 입력 및 중간 결과를 UTF-8 기준 16 MiB로 제한한다. 제한 깊이를 넘겨 마커가 남아 있으면 오류로 중단한다.

복호기는 페이지에서 확인한 `enc숫자` 버전과 응답 접두사가 일치하는 경우 기존 Base64 인증·복호화 규칙을 적용하며, `enc1`만 Hex로 처리한다. 따라서 같은 암호문 형식을 유지한 버전 변경에는 허용 목록 수정이 필요 없다. 알고리즘이나 요청 구조까지 바뀌는 경우의 자동 호환을 보장하는 것은 아니다. 예상과 다른 응답 접두사 및 인증값은 계속 거부한다.

AES-CBC와 PKCS7 처리는 유지보수되는 `pycryptodomex`의 네이티브 구현을 사용한다. `pycomcigan/_aes.py`는 입력 검증과 라이브러리 호출만 담당하며, 별도의 AES 알고리즘 구현을 포함하지 않는다. HMAC-SHA256과 인코딩 검증은 Python 표준 라이브러리로 처리한다. HMAC 인증이 성공한 뒤에만 복호화하며, 범용 암호 API로 노출하지 않는다.

HTTP 요청은 기존 `requests`를 유지한다. HTTP 전송 계층의 의존성 제거는 enc5 복구와 독립적인 변경이므로 별도 PR에서 다룬다. 런타임 직접 의존성은 `requests`와 `pycryptodomex`이며, PyCryptodomeX 자체에는 추가 런타임 의존성이 없다. 테스트·빌드·게시 도구는 개발 의존성으로 분리한다.

## 2026-11-09 복호화 성능 비교

`425200d`의 순수 Python AES와 `cryptography 50.0.0`의 네이티브 AES를 동일한 실제 중일고등학교 응답으로 비교했다. Python 3.12.14 / Linux x86_64 / AMD EPYC 9V74 환경에서 한 번의 워밍업 후 11회 반복한 중앙값이다. 측정 구간은 AES-256-CBC 객체 생성·키 설정과 원시 복호화이며, 네트워크·Base64·HMAC·PKCS7 제거·UTF-8·JSON 처리는 제외했다. 두 구현의 복호화 바이트와 최종 JSON은 일치했다.

| 응답 / 암호문 크기 | 순수 Python AES | 네이티브 AES (`cryptography`) |
|---|---:|---:|
| 29,155 B / 21,808 B | 124.678319 ms | 0.007151 ms |
| 23,203 B / 17,344 B | 93.792982 ms | 0.006139 ms |

위 수치는 비교 당시의 `cryptography` 측정값이며, 이번에 복원한 PyCryptodomeX의 측정값으로 제시하는 것은 아니다. 의존성 최소화의 이점은 인정하지만, 성능과 AES 구현의 정확성·보안 수정·유지보수 부담을 고려해 검증된 라이브러리를 사용하는 쪽을 선택했다.

## 추가 변경: 요청 토큰 헤더

같은 날 후속 변경으로 `/st` 페이지가 `window.__HourRequestToken`을 발급하고, 학교 검색과 시간표 요청 모두 `X-Hour-Token` 헤더로 전달하도록 바뀌었다. 요청 토큰 없이 기존 enc5 요청을 보내면 현재는 HTTP 403이 반환된다. 아래 초기 검증의 HTTP 200 / `{}` 기록은 토큰 도입 전 결과다.

두 요청 함수에서 토큰 헤더 사용이 일치하는지 확인하고, 페이지의 리터럴 토큰만 읽어 해당 페이지에서 추출한 경로·키와 함께 사용한다. 토큰을 요구하는 페이지에 토큰이 없거나 형식이 잘못되면 요청 전에 중단한다. 토큰을 전역 헤더나 `ServiceProtocol`의 repr에 포함하지 않으며, 실제 발급 토큰은 코드·테스트·문서에 저장하지 않는다. 토큰 헤더가 없는 이전 페이지도 계속 처리한다.

HTTP 403은 요청 거부·토큰 만료 가능성, HTTP 429는 요청 제한으로 구분해 `RuntimeError`를 낸다. 그 밖의 HTTP 오류는 `requests.exceptions.HTTPError`로 전달하며, 오류 본문을 복호화하려고 시도하지 않는다. 네트워크 오류는 `requests`의 예외로 전달한다. 요청 제한 시간은 30초다. 자동 재시도나 토큰 재발급 반복은 추가하지 않는다. 호출을 새로 시작하면 새 페이지에서 토큰을 읽는다.

토큰 도입 후 실서버에서도 검색 결과 10개, 없는 학교 검색 0개, 아래 두 주차의 시작일·수업 수가 동일하게 조회되는 것을 재확인했다. 발급 토큰을 누락한 요청은 HTTP 403, 해당 토큰을 정상 헤더로 보낸 요청은 HTTP 200 및 `enc5` 응답을 반환했다.

## 검증
